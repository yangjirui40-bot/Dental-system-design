# 使用手册

网页登录版本1.5.2。网页入口：https://api.yjr-adc-demo.xyz/。教学身份的密码显示在密码框下方。网页和小程序共用云端教学库。教学操作请使用虚构信息。个人账号和微信绑定仍访问原有档案。

## 1. 按岗位进入

员工在网页的“登录身份”中选择前台接待、牙医、诊所主管、总部业务、总部财务或总部负责人，输入教学密码后登录。患者在小程序点“账号密码登录”，选择“患者本人”或“授权代办人”，再输入教学密码。使用个人账号时选择“使用自己的账号”。切换身份会清空已输入的密码。

登录后只显示该岗位有权办理的业务。在“我的”中切换已授予的岗位和门店；不能通过切换自行增加授权。患者可在注册入口建立本人账号；代办账号注册后须由门店核实具体患者及授权事项。已有档案请绑定原账号，不通过同名或电话自动接管。代办事项、期限及临床同意资格分别核实，紧急联系人不自动成为代理人。

## 1.1 微信验证、注册和账号找回

微信入口先阅读并同意隐私说明，再进行官方微信验证。已有绑定时只列出该微信已经核实的业务账号及有效门店/患者范围，选择身份不会增加权限。首次使用可登记患者本人，或建立待授权代办账号；工作人员选择身份后仍须验证原工作账号密码。一个微信可关联本人已经验证的多个业务账号。

注册患者需填写姓名、出生日期、联系电话、通讯地址以及紧急联系人的姓名、电话和关系；过敏状态按实际申报，逐项申报需填写物质与反应。微信已验证时可不设独立密码；普通注册须填写登录账号及至少12位密码。使用课程合成资料，未满14周岁走门店监护核实流程。代办注册完成不代表已经取得患者资料或临床同意权。

已绑定微信的账号，可从“忘记密码”或“我的 → 找回或设置账号密码”重新验证微信后设置密码；完成后旧会话及旧找回凭据失效。未绑定时按页面真实邮箱或门店渠道核实，不提供尚未实现的短信验证码。换绑由UC16有权人员核实并填写依据，解除后相关微信会话立即失效。

患者端沿用已通过手机验证的云开发通道。底部“我的预约”查安排，“就诊与费用”查治疗和账单，“我的”进入资料；顶部“导航”按预约、账单、联系人等关键词查找。点击填写区不会收起面板；主动收起后再次打开同一事项保留本页草稿。会话失效时在原页核验同一账号，成功后继续填写，不自动提交；主动退出登录会放弃内存草稿。

## 2. 患者预约、改期和治疗接续

1. 首页点击“预约医生”，选择就诊人、门店及有已发布出诊的日期。
2. 可以按拟治疗项目预约，也可以“先做初步检查”并填写就诊诉求，无需自行确定诊断。项目尚不明确时，参考费用显示待检查后据实确定。
3. 阅读可约医生的照片、简介、已核实资格及教学资料说明，打开资料详情后选择医生和完整时段。
4. 核对门店、医生、日期、时长和诉求，确认后取得预约编号。没有合适时段时更换日期或门店，不反复提交同一安排。
5. 在“我的预约”查看原约、变更原因及新约关联。改期先选择新时段并填写原因；失败时原约继续保留。取消也保留历史。
6. 当日实际到店后报到；需要协助时由前台办理。报到不等于已经接诊，实际接诊由牙医核实。
7. 在“就诊与费用”查看牙医已确认的阶段及先决关系。阶段只有在放行、前序完成且没有现行预约等条件满足后才能约。预约取消后，仍需治疗的阶段进入待约接续，不自动算完成。
8. 查看有效结算及副本。如对费用有疑问，向门店提供原单号和版本；正常规则内开单不需要主管逐单批准。

## 3. 前台与门店主管

- “患者资料”：先检索并核实身份。同名或共用电话时核对出生日期及账单地址，明确为不同患者后记录依据，不直接合并原账号。联系人用途与授权分别保存。
- “预约与就诊安排”：可以协助预约变更和报到。点击“例外待约与责任”进入联系记录；保存实际联系结论及下次期限。主管可在办理菜单中移交待约责任，接手人必须具备该门店有效办理岗位。
- “到店与接诊”：前台核实未到或到店未接诊离开；未到只能在原时段到期并核实后记录，不能按系统时间自动推断。
- “出诊与排班”：选择安排，进入协调面板，保存协调稿并查看影响。约定不变的预约只迁移出诊引用；医生、门店或时点改变时逐患者记录新约及明确同意，再一次发布。条件未满足时保留原安排及协调稿。
- “登记真实停诊”：仅在原出诊实际无法履行时使用。系统阻止新约，原约按机构原因保留，并进入自助改约及门店例外接续。已经接诊的事实保持原样。
- “营业与诊疗资源”：先查看现有安排影响。计划调整先解决已有承诺；真实临时停业或故障选择立即不可用，填写真实原因并确认接续责任。
- “费用结算”：按实际就诊核对项目、数量、单价和有效/待核实版本；非标准价格和费用更正由独立主管批准。前台不能猜测项目，也不能代填牙医零费用依据。结算副本在桌面可打印或保存PDF。

## 4. 牙医

1. 在“到店与接诊”选择本人负责、已经报到的预约，核实身份和过敏后确认实际接诊。
2. 在“诊疗记录”选择实际就诊，记录病史、检查、诊断、处置、注意事项、逐项实施及患者同意依据。未明确的事实先保存草稿；待核实事项可单独保留，不虚构同意或有效结算。
3. 签署前核对实际数量、部位、价格和承接阶段的结果。非标准价格先保存草稿并由主管批准。实际签署后按规则生成业务结算。
4. 已签署记录通过更正处理，保留稳定治疗编号和原实施时间。仅文字变化不重开账单；费用事实变化保留原有效账单，形成待核实版本。
5. 在“阶段治疗方案”从实际就诊建立方案，逐阶段明确承接门店、临床条件、项目、时间窗口及先决关系。草案可以重新打开，原有阶段和实际就诊绑定必须保留。
6. 仅确认未改定义的既有草案时，沿用原修订号；定义变化按修订处理。先处理受影响预约，再确认新定义。放行不能越过未完成的先决阶段；暂停或终止先办结本次实际接诊和未解决预约。

## 5. 总部业务、财务与负责人

业务人员依次维护门店、职员及牙医身份、资格证照、营业资源和出诊。项目目录与有效标准分开，草案由独立负责人核实批准。未批准、失效或停用项目不能作为新预约的有效选项。

财务按原始凭据录入来源费用，按牙医、门店和季度填写分摊及依据；分摊合计必须与来源金额相等。主管复核归属及两类费用齐备声明，异议保留原因；录入人不能审批自己的费用。

负责人在“季度经营分析”先看履约与原因、治疗接续、技能供需、标准核查，再查看季度财务。未核实预约、临床修订、未开单就诊或未复核/缺报费用会阻止正式确认。集团净利润先合计，只有合计为正才计10%基金。

正式确认固定财务来源版本。后续批准更正后原报告标为待重核；历史报告仍显示当时的来源及金额。实时运营指标按当前时点展示，不冒充历史冻结值。

## 6. 账号、追溯和日常维护

前台仅开通患者及代办账号；职员岗位由负责人授权。主管、接待岗位逐店授权，跨店需相应门店范围。跨店牙医仍只能访问本人接诊及负责方案所需患者。

停用账号会立即阻止登录，保留业务责任和历史。主管明确接手人及期限，未办事项不能随账号停用消失。

在“操作记录”按时间、账号、业务、编号、操作和结果筛选，查看前后版本和有权访问的原业务。打开原业务时会重新检查当前权限。

日常出诊需要主管持续发布，不会无限自动生成。服务器备份及恢复步骤见CLOUD_OPERATIONS.md；关闭本机启动窗口或停止本地服务不会删除云端或数据库持久卷。

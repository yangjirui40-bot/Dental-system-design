# ADC 牙科诊所小程序实现设计

## 1. 页面核心与业务基线

依据20261102《ADC牙科连锁诊所——系统分析与设计》最终稿、原型及配套SQL。原Word、PDF、drawio保持原样；文档/SQL指纹见`contracts/source-lock.json`；17项用例和14项不变量见`contracts/design.json`。

**核心：患者自主取得完整可约时段，临床人员确认实际服务，经营数据沿实际诊疗和复核费用形成。** 正常选约、改期、报到和查询不插入前台审批；身份未核实、代办授权、停诊及临床例外才交相应岗位处理。整体传递清楚、安定、可靠和责任明确的感觉，信息优先于装饰。

|业务概念|必须保持的含义|
|---|---|
|可约|营业、完整排班、有效资格、医生/患者/诊疗位占用、阶段先决同时满足；保存时重核|
|到店/接诊|患者报到不生成实际接诊；实际接诊由有权牙医核实|
|计费/结算|已签署实际实施数量和价格快照；结算单不表示在线支付成功|
|治疗接续|稳定阶段身份、先决关系和有效方案版本，不能重新抄建一个疗程|
|季度确认|费用齐备、归属复核、来源集合固定；缺报不能当零|

## 5. 按受众组织首屏与业务页面

20261112修订保留原17项用例、14项不变量和58张表。后续用户明确要求增加医生照片与简介，作为公开展示资料补充；不改写既有患者、临床、资质和预约实体。参考站仅用于学习信息组织，不复制商标、照片或文案。

患者端采用轻量的就诊服务界面：问候与当前日期后呈现诊所场景图和预约主入口；四项常用服务以图标和文字横排，不加四个方框。下一次预约用日期、门店、医生、时段和下一步动作组成一条记录；治疗接续优先显示可继续安排的阶段。最近记录控制在两条，不让取消历史占据首屏。空状态用一行说明，不生成占满半屏的空白卡片。

桌面使用240px白色侧栏和72px顶栏，内容最大1344px、左右32px。患者首页的图文区高260px，图像在右60%，文字区在左47%，同为白色底；手机高188px。患者端正文以分区、间距和分隔线组织，取消默认的统计卡阵列。图标采用DCloud官方uni-icons，同一图标家族。

预约分为就诊安排、医生与时段、核对确认和保存结果。患者先选择门店、日期及项目，再查看满足本次条件的医生。医生列表使用照片＋姓名＋简介＋资格＋查看资料＋选医生的条目布局，照片桌面100×125px、手机78×102px；不把每位医生变成一块重复的大卡片。医生详情桌面居中、手机从底部呈现。上午和下午切换，每次显示一组完整安排；时段使用340px高且不超过46vh的滚动区。阶段预约沿用已确认的门店和项目，不允许在客户端悄然改写计划。

预约核对必须包含患者、门店、具体牙医、诊疗位、完整时段、项目及实际渠道；预计金额不能表示已经收费。保存前后端再次核验。详情同时提供原约、新约、事件时间线、实际接诊及有效结算的关系。

工作人员采用适合处理业务记录的工作台：首页统计使用无框文字摘要；今日安排和业务入口使用日程或列表。业务页先呈现已有记录，按患者、门店、资质、阶段、费用等领域给出不同列和状态；选中记录显示业务详情，需要办理时打开面板。诊疗面板区分就诊依据、检查与诊疗记录、患者同意、实际实施明细；方案面板保留稳定阶段和先决关系；季度页区分来源问题、分项金额与集团基金。表格适用于工作人员核对，不套用到患者首页。

手机680px以下隐藏桌面侧栏，使用顶部内容导航行和底部四项导航。微信顶部按实际状态栏与胶囊留位，办理面板也避让系统区域；底部52px加安全区。全部业务使用单独的搜索与分组页面，不用延时滚动模拟导航。登录页桌面以诊所场景图配合账号表单，手机为短场景图和直接输入；没有未经规约约定的公开注册或微信一键身份绑定。

## 1.1.0补全页面与办理规则

- 出诊页采用日期与医生列表、安排详情和侧边协调面板。协调稿在原出诊表保存；原约不受影响时不增加患者审批，变更约定要素时逐人核对新时段和同意依据。真实停诊与普通调整使用不同入口。
- 经营页分为履约与原因、治疗接续、技能供需、标准核查、季度财务五个标签。指标同时呈现样本与分母；零样本显示“不适用”。机构原因单列；实时运营与冻结财务版本分别标识。
- 操作记录页提供日期、账号、业务、原编号、操作和结果筛选；详情呈现真实前后版本和权限受控的原业务入口。
- 结算副本沿用原单号与有效版本，采用白纸、黑灰文字和细分隔线，桌面可打印或存为PDF；打印隐藏导航和操作按钮。患者不能借副本读取病历正文。
- 新面板沿用原色板、字体、按钮、间距和120ms按钮状态反馈。所有业务请求由明确点击触发；请求期间禁用重复提交，失败保留表单和同一请求凭据。不加入持续闪烁、自动轮播或装饰性入场动效。
- 微信自定义面板避开状态栏与胶囊，底部保留安全区；H5日期控件的官方基础样式在入口预加载，避免异步表单短暂显示滚轮原始列表。
# 登录连接诊断补充（2026-11-12）

患者真机反馈登录连接失败后，登录页增加“检查连接”文字按钮，使用相同正式HTTPS域名只读访问健康接口。结果在原登录表单内显示，不导航到工作人员页面。网络失败保留微信返回的错误类别与编号，供定位域名、证书、超时等差异；不输出账号口令、登录凭据或业务正文。版本号用于识别缓存旧包。该入口沿用原蓝色文字、12px辅助文字和原错误颜色，不新增主色；请求中按钮禁用，结束后恢复，无额外动画。

## 认证入口补充（1.2.0，2026-11-13）
